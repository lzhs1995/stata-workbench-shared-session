# 显式共享执行、允许隐藏与并发边界

2026-10-01 文档经验更新。适用时先核对实际安装的运行时和客户端；本页不安装、
重启或修改 backend，也不为公共版本添加未经实现的 CLI 参数。

## 显式执行与窗口状态

显式共享执行：用户可定位正在执行的 `.do`，人和 AI 通过已绑定的 Workbench
实例使用同一个 Stata backend，请求、实际执行代码、日志及输出均可核对。
窗口处于前台、未遮挡，是另一项可见性观察。

默认展示源码和 Stata Terminal。用户明确允许遮挡、隐藏或最小化后，将其记入
任务执行策略；只要原实例、执行通道、代码身份、会话状态和任务依赖仍可验证，
非 UI 阶段可继续。不反复激活窗口，不为恢复无遮挡重跑成功计算，不因看不见
窗口推断 backend 已停止。隐藏不等于退出应用；不要另起后台 Stata 绕过共享实例。

可见性要求仍严格的任务，在可见性丢失后核收原请求，再处理后续布局。新授权
不追改旧回执：历史可见性失败保持失败。允许隐藏也不等于获得了画面、页面布局
或人类实际观看的证据。

必须区分普通遮挡与 renderer 无响应。对无响应、身份变化、未知请求终态先查原
执行记录，不能把它们一律解释成允许隐藏。系统锁屏不应被绕过；需 GUI 的操作
等待正常解锁，独立离线核验可以继续。

## 一次提交与阶段接续

每阶段绑定 profile、launcher/extension host、bridge 端口、backend 身份、代码
SHA、输入、独立输出目录、requestId/runId。保持同一 backend 的人机提交串行，
读取真实终态和输出后再推进。HTTP 成功、控制器 exit 0、文件存在和模型成功
分别核验；这些事实不互相替代。

请求不确定时保留日志、部分输出及进程证据，查原请求而不重发。控制器停止不
说明其子进程已停止；子进程输出诊断完成也不能补造原 wait exit 0。必要时另存
补充核收记录，注明原 unknown 仍保留，再从已证明未提交的阶段接续。

取消后续阶段应让当前已提交阶段自然收尾；取消当前计算使用产品相应控制，并
核实终态。不要以强杀共享 backend、清空人类数据或覆盖冻结回执完成收尾。

## 三种并发分别记录

| 场景 | 执行约束 | 可以声称的结果 |
|---|---|---|
| 两个操作者共用一个 backend | 一个提交队列；共享 frames、宏、估计、图与会话状态 | 人机共享、轮流提交 |
| Stata 计算与离线核验/归档 | 核验只读已冻结输入；新输出目录分开 | 计算与独立文件工作并行 |
| 两个独立 Workbench 实例 | 各实例身份、端口、会话状态、输出与锁分别绑定 | 仅在实际重叠执行及无串线验证后称多实例统计并发通过 |

多开窗口不一定产生独立 backend；不同端口也不足以证明隔离。多实例使用前应：

1. 给每个实例独立 user-data/profile 和工作区，固定各自 launcher、extension host、
   backend PID/owner 及 loopback bridge 端口。不要按“第一个窗口”或进程名模糊选择。
2. 分开输出、临时文件、回执和客户端执行锁，核查 Stata 许可、内存及磁盘容量。
   两个任务可以读取不可变原始数据，但不能同时写相同文件或共用可变中间库。
3. 确认所用客户端支持这些绑定。当前公共 `tools/verified_workbench.py` 面向一个
   固定实例；任务中的固定客户端也可能含固定 PID、端口及全局锁。不能删掉
   duplicate-instance 防护、随意改锁名或仅改端口就宣称支持多实例。
4. 使用非研究数据在各实例读写不同标记，证明请求、结果、取消和恢复不会串线；
   保存真实时间重叠和各自终态。未执行该验证时写“隔离规范，尚未实测”。

共享桌面的焦点、键鼠、剪贴板和 Office 等 UI 操作仍需统一短事务协调。沿已有
资源队列和同一锁文件 inode；如约定输入空闲窗口，则在锁内重新检查。8 秒是
本次研究工作区的约定，不是插件通用硬编码。无 UI 的计算无需持有焦点锁；释放
焦点锁也不等于统计 runner 已终态或资源 broker 票据已归还。

## 本次实测范围与产品限制

本机研究任务使用 `0.1.3-rc.7.43-dev.1` 和固定的任务客户端，在用户授权后通过
原 Workbench 通道完成遮挡允许模式的请求，保留一次 POST、请求/完成标记、
原生输出与单列物理可见性记录。这是本机特定运行时/客户端的经验，不能升级为
公共 `rc.7.39`、候选 `visible-cowork/1` 或其他系统的实时验收。

本次更新没有新做隐藏/最小化状态下的逐状态试验，也没有启动两个 Stata 实例做
同时拟合；允许隐藏是任务执行政策，多实例部分是隔离和验证规范。现有客户端
若仍以窗口计数作门禁，文档本身不会改变其实现；需要经过审查的匹配客户端，
不能伪造窗口数、ready 或 PASS。

## 研究文件与可复用经验

从原始数据到筛选、清洗、编码、合并及导出，记录真实依赖与原作者来源。修改
用 Stata `***`、`//` 或 `/* */` 注释说明原逻辑、依据、改变和未决问题，保留
作者命名和风格。原始库、A 原逻辑、B 有据修订与冻结失败分开。

条件模型失败时不生成虚构 `.ster`，不使用上一模型残留的 `e()` 预测；将成功、
失败、复用和未提交分别列明。合法的重复遗漏项名称或 `V_modelbased` 自身轴名
不能仅因不满足核验器假设就判模型失败。显示精度、全矩阵数值、跨次重放、
物理可见性和科学解释分别给结论。

交付可顺序运行的 DO 与输入输出索引；“禁止整体执行”的审阅副本只能作说明。
更新范围立即覆盖旧自动调度，但保留已完成结果。数据差异说明不自动触发下游
R 重估、改稿或新的敏感性研究。

公开仓库只保存通用规则和适用范围。研究数据、个体标识、私有回执及凭据留在
本地。源码、文档已安装、扩展已加载和真实运行验收应分别报告。
